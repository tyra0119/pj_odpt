01 — 着想

塗り分けではなく、消灯を主役にする

「カバー率85%」と言われても何も感じない。だが真っ暗な地図に灯りが点々と散っている絵は、 一目で伝わる。この企画は発想を反転させ、データが無いことのほうを描く。

そのためには「本来あるべき全体」——分母が要る。公開されているデータを並べるのは誰でもできるが、 無いものを描くには全事業者・全路線の母集団を先に定義しなければならない。 そこがこの企画の技術的な心臓部になる。

なお「無い」は3種類ある。この区別を守ることが、単なるカバレッジ地図との決定的な差になる。

A
集約の空白ODPTには無いが、gtfs-data.jp や事業者の自社サイトには存在する
B
真のデータ空白どこにも機械可読データが無い。PDF時刻表のみ
C
交通空白地域そもそも交通事業が存在しない。データの問題ではない

B と C を混ぜないこと。事業者に対して事実と異なる表示をすれば、企画の信頼性は一発で壊れる。 判定できないものには「未確認」を必ず持たせる。

02 — 検証

実際に叩いて分かった三つの事実

企画の前提が成立するかを先に確かめた。結果、想定していなかった構造が2つ見つかった。

① 全体像を一望できる場所が、現時点で存在しない

ODPT CKAN の129組織と gtfs-data.jp の438事業者を突合したところ、一致はわずか12者だった。 京都バス・伊予鉄バス・東急バス・小田急バス・神奈川中央交通は ODPT にのみ登録され、 gtfs-data.jp には1件も存在しない。逆に地方の420事業者あまりは ODPT に居ない。 事業者名での照合と、10万件の停留所座標を使った照合という独立した2つの手法が、 同じ結論を出している。

② ODPTの2つのAPIは、上位互換ではなく別カタログだった

センター用トークンとチャレンジ2026専用トークンは、単なる権限差ではなかった。 ホストが異なり（api.odpt.org と api-challenge.odpt.org）、内容は包含関係にない。

開発者は2つのトークンを持って初めて全体が見え、しかしどちらか一方だけでは実サービスを出せない。

鉄道路線を持つ52事業者のうち、27事業者は通年APIに一切登場しない。 銚子電鉄、江ノ島電鉄、秩父鉄道、宇都宮ライトレール、いすみ鉄道、わたらせ渓谷鐵道、 JR西日本、JR四国——いずれもコンテスト期間中しか地図に描けない。

③ 名寄せは実現できる。ただし文字列類似度は使えない

事業者名の類似度マッチングを試したところ、候補7件がすべて誤検出だった。 「村山市／東村山市」「津市／唐津市」「東濃鉄道／東武鉄道」。 日本の自治体名・事業者名は編集距離が近すぎ、スコアは誤接続しか生まない。

代わりに (都道府県, 市区町村名) の完全一致だけで、 gtfs-data.jp の438者中356者（81.3%）を全国地方公共団体コードへ決定的に結合できた。 外れた自治体名は実質1件である。

さらに有効だったのが、停留所の座標による照合だった。 gtfs-data.jp の10万件と ODPT 配布 GTFS の5万件を半径50mで突合すると、 一致率の分布に中間が存在しない——98.9%以上が10件、11.7%以下が91件で、その間が空白になる。 閾値の設定に迷う余地がない。

この方法は「国立市道路交通課／国立市」「三豊市（香川県）／三豊市」のように、 名前では外れる同一事業者を拾う。一方で GTFS を持たない事業者は座標が無いため拾えず、 七ヶ浜町は名前照合でしか見つからなかった。両方を走らせて和を取る。

低い一致率の帯も無駄ではなかった。西武バスと軽井沢町の192組は誤検出ではなく、 実在する停留所の共用である（誤差0.4〜2.2m、159組は停留所名も一致）。 ある市区町村が「データあり」に見えても、それはコミュニティバスの GTFS だけで、 同じ停留所を通る幹線の民間路線にはデータが無い——という状態がありうる。 カバレッジは停留所単位で見ないと取り違える。

そして地図の上部にトグルを1つ置く——コンテスト終了日、2027年3月13日。

192 本 ／ ODPT にデータがある鉄道路線
ODPT 85 ODPT（期間限定） 107

107本が消え、リアルタイムの脈動が止まる。カバー率を数字で語るより、はるかに速く伝わる。

「消えても、どこか別の場所にデータはあるのでは」——そう考えて確かめた。 107路線のうち、gtfs-data.jp にもデータがあるのは1路線だけだった （JR弥彦線。燕市が出しているフィードに含まれる）。残る106路線は、その日を境に 機械可読なデータが日本のどこにも無くなる。

これは批判ではない。通年ライセンスへの移行が進めば、この地図は消えなくなる—— そういうメッセージとして設計する。

指標は面積ではなく人口で出す

500mメッシュ人口（国土数値情報・全国47万メッシュ）で重み付けして、鉄道について実際に算出した。 駅から1km以内を駅勢圏とし、その人口を最も条件の良い路線の状態へ配分している。

ODPT2,386万人19.0%
ODPT（期間限定・2027-03-12まで）770万人6.1%
ODPT外74万人0.6%
なし3,078万人24.6%
駅勢圏外（駅から1km以上）6,225万人49.7%

読み取れることが3つある。まず、日本人の半数は鉄道駅から1km以上離れて暮らしている。 次に、駅の近くに住んでいてもその半数（48.8%）は路線のデータが無い。 そして通年で使えるデータの恩恵が届くのは、国民の19.0%——5人に1人にとどまる。

そして 2027年3月13日、770万人分の鉄道情報が消える。 千葉県の人口より多い。駅勢圏人口の12.2%にあたる。

見て終わりにしない

地図上で「なし」の路線・停留所にカーソルを合わせると、その事業者あての 公開依頼文がその場で組み上がり、ひと押しでコピーできる。 可視化を運動に変える導線を、閲覧のすぐ隣に置いた。

さらに、算出したカバレッジデータ自体をオープンデータとして公開している。 オープンデータを使うアプリではなく、オープンデータを増やすアプリという立ち位置を取る。 副産物の事業者名寄せ辞書——ODPT / gtfs-data.jp / 国土数値情報 の対応表——は、 この界隈が共通で欲しがっている資産でもある。ODPT CKAN への登録も申請する。

05 — 位置づけ

先行事例との違い

GTFS の公開状況を地図化した先行事例はある。西澤明氏の「GTFSオープンデータマップ」、 T.Shimada's Data Lab. の公開データ一覧と年度別統計。いずれも価値の高い仕事だが、 対象はバス／GTFS に限られる。

6モード横断でもなく、ODPT 登録の有無も、ライセンスによる実用可否も扱っていない。 本企画が埋めるのはそこである。

07 — リスク

いちばん弱いところ

分母の網羅性が最大の弱点になる。国土数値情報は更新が遅く、バス路線データは特に古い。 対策は、推定値であることを明示したうえで、算出データも GitHub で公開し、 Issue / PR で市民が修正できる構造にすること。弱点を参加型プロジェクトという性質に反転させる。

もうひとつ。「gtfs-data.jp にフィードが0件の府県が7つある」といった観測は、 事業者が自社サイトで公開しているだけの可能性が高い。断定表示は誤った批判になるため、 A / B / C の分類と「未確認」ステータスを厳格に守る。
